# yk-qshell

A desktop shell for Wayland and Hyprland, written in QML with [Quickshell](https://quickshell.outfoxxed.me/),
whose view of the system comes from a [Yoke](https://github.com/yoke-project) application: what the shell
shows of the CPU, the memory, the network, the power and Bluetooth is what the application's Plugins say,
read through the interface contract with the QML binding of `yoke-sdk-cpp`. What belongs to the compositor
or to the shell itself — workspaces, the tray, the launcher, audio — stays Quickshell's.

It is also a practical case for Yoke: where the shell needs something Yoke does not offer, the answer is
made in Yoke, not worked around here.

## Status

The first piece: a bar showing CPU and memory from the pool's `hw-monitor`. The rest of the shell follows,
one service at a time.

| Service | From |
| --- | --- |
| `SystemStats` — CPU, memory, swap | `hw-monitor` 0.4.0 (streams `hw.cpu`, `hw.memory`, question `hw.snapshot`) |

## Layout

| Path | What it is |
| --- | --- |
| `app/` | The Yoke application, made with `yoke-compose`: its Plugins (`plugins.yaml`, `manifests/`) and the channel `shell`, a local socket for one client, that no unit is launched for |
| `shell/` | The Quickshell configuration. `services/Yoke.qml` holds the one attachment to the channel; each service built on it joins a Plugin's present to what follows, by the sequence the Plugin states |
| `scripts/run.sh` | Runs the application on a local Core, grants its Plugins what they declare, and starts the shell beside it |

## Running it

Yoke's programs, 0.16.0 or newer:

```sh
for p in yoke yoke-compose yoke-core yoke-guardian yoke-auth; do
  go install "github.com/yoke-project/yoke/cmd/$p@latest"
done
```

The QML binding, from `yoke-sdk-cpp`, installed where Quickshell can import it. On a distribution whose
protobuf is not the one the family's committed definitions were generated with, `just build-here` builds it
on definitions generated by the machine's own `protoc`:

```sh
git clone https://github.com/yoke-project/yoke-sdk-cpp && cd yoke-sdk-cpp
just build-here        # or `just build` where the committed definitions compile
cmake --install build-here --prefix ~/.local
```

Then, with the import path that holds `Yoke/Interface`:

```sh
scripts/run.sh ~/.local/lib/qt6/qml
```

The first run builds each Plugin from the tag `app/plugins.yaml` records.
